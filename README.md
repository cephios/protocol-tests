# Cephios Protocol — conformance test-vector suite (v1.0 bootstrap)

This is the **v1.0 bootstrap** of the Cephios Protocol conformance test-vector
suite. It is the staging copy that the Founder publishes to the public
`cephios/protocol-tests` repository as the operational close-step of Group 11
(`MVP_MAP.md` §4 Group 11; `ROADMAP.md` §7 row 11). The published artifact is
**"The Cephios Protocol, version 1.0"** — the wire protocol version per
`CONTRACT_SPEC.md` §15.6, distinct from the `CONTRACT_SPEC.md` document revision.

## What "bootstrap" means (read this before trusting a green runner)

Per `CONTRACT_SPEC.md` §17.4, the steady-state discipline is **dual-source
generation**: vectors are generated by `cephios-core` (Python) and independently
cross-verified by `@cephios/core` (TypeScript); a disagreement holds the vector
until resolved. Those two reference implementations do not exist yet — they are
Groups 12 and 13, which depend on this suite. So the v1.0 suite cannot be
dual-source-generated at Group 11; it is **bootstrapped**:

- **Implementation-oracle categories** (`envelope_encryption`, `wrapped_dek`,
  `envelope_versioning`; the typed-error mapping in `error_taxonomy`) take their
  canonical bytes / dispositions from the **reference Go implementation**
  (`internal/envelope`, `internal/cepherror`).
- **`key_derivation`** takes its bytes from a **named external authority** (an
  offline Argon2id run with the `CONTRACT_SPEC.md` §4.2 parameters), because the
  derivation is client-side per §5.3 and there is **no server-side Argon2id**
  (the `auth-no-argon2` discipline; key custody).
- **Shape categories** (`ingestion_idempotency`, `session_lifecycle`,
  `control_plane_erasure`, and the HTTP-shape vectors inside `wrapped_dek`) pin
  the wire request/response shapes from `CONTRACT_SPEC.md` §7–§10.

The in-repo Go runner (`internal/sdk_sketch/conformance_test.go`) is a
**bootstrap-sanity check**: it confirms that the published bytes match the
reference Go oracle for the implementation-oracle categories. It is **NOT** the
conformance proof. The real conformance proof is the **independent dual-source
cross-verification at Groups 12/13** (`CONTRACT_SPEC.md` §17.4): a green Go
runner shows the bytes are self-consistent with the Go reference, not that the
spec is correct or that two independent implementations agree.

## Layout

```
v1.0/
├── envelope_encryption.json      # AES-256-GCM construct/deconstruct (§6.4/§6.5) — Go-oracle
├── wrapped_dek.json              # X25519-ECIES unwrap (§6.3) — Go-oracle; + §8 HTTP shapes
├── key_derivation.json           # Argon2id master-password derivation (§5.3) — EXTERNAL authority
├── ingestion_idempotency.json    # POST /v1/ingest persisted/deduplicated shapes (§7)
├── error_taxonomy.json           # typed CephiosError category/code/status (§14)
├── envelope_versioning.json      # version/alg_id rejection (§6.5 steps 3-4)
├── session_lifecycle.json        # open/close shapes (§9)
└── control_plane_erasure.json    # DELETE /v1/subjects/{id} shapes (§10.5)
```

Each file is a JSON array of `CONTRACT_SPEC.md` §17.2 vector objects
(`test_id` / `category` / `protocol_version` / `description` / `input` /
`expected_output` / `notes`). For non-deterministic primitives the conformance
direction is the deterministic one: `wrapped_dek` pins a fixed reference wrap
envelope and tests **unwrap** (forward wrapping uses a fresh ephemeral per
§6.3 step 1 and is not reproducible).

## `runners/` is NOT part of this Group-11 publication

`CONTRACT_SPEC.md` §17.1 describes a `runners/{python,typescript,community-examples}`
tree. Those reference runners are populated by **Groups 12/13** (the Python and
TypeScript reference SDKs) and are intentionally absent from this v1.0 bootstrap.
A community implementer in any language builds their own runner that decodes
these vectors and exercises their implementation.
